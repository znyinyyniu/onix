## 新增需求

### 需求：GPT 头校验

系统必须通过读取 LBA 1 并校验签名 `EFI PART`、头大小及支持的版本来识别 GPT 磁盘。

#### 场景：有效的 GPT 磁盘

- **当** LBA 1 包含有效的 GPT 头时
- **则** 使用分区表项数组继续执行分区解析

#### 场景：非 GPT 磁盘

- **当** LBA 1 不包含有效的 GPT 头时
- **则** GPT 解析失败，且不注册任何 GPT 分区

### 需求：分区表项提取

系统必须读取 GPT 分区表项，并为每个非空表项提取起始 LBA、结束 LBA（含）、分区类型 GUID 及分区名称。

#### 场景：双分区 U 盘布局

- **当** U 盘 GPT 包含 P1（ESP）和 P2（Minix）表项时
- **则** 注册两个分区设备，且起始 LBA 与扇区数量正确

### 需求：保护性 MBR 不得当作数据分区

系统不得将保护性 MBR（LBA 0，类型 `0xEE` 覆盖整盘）注册为可挂载的数据分区。

#### 场景：GPT U 盘 LBA 0

- **当** 仅对 GPT U 盘 LBA 0 套用 MBR 风格解析时
- **则** 该路径不得用于 USB 根挂载（应改用 GPT 路径）

### 需求：USB 分区块设备

U 盘上每个已解析的 GPT 分区必须暴露为块设备，提供与 IDE 分区设备等价的读、写及扇区 ioctl 操作。

#### 场景：读取 P2 扇区

- **当** 内核读取 USB GPT 分区索引 1 的扇区 0 时
- **则** 返回的读数据来自正确磁盘 LBA 上的 Minix 超级块扇区
