## 新增需求

### 需求：USB 启动镜像优先从 USB 挂载根

在 USB 启动构建配置下，系统必须从第一块可用 USB 块设备的 GPT 分区索引 1（第二分区）挂载根文件系统，且不得依赖 IDE 磁盘。

#### 场景：纯 USB 单盘启动

- **当** 内核从 UEFI U 盘镜像启动，且仅连接 U 盘作为存储设备时
- **则** `mount_root` 成功挂载 USB GPT P2 上的 Minix 文件系统

### 需求：可写 Minix 根文件系统

已挂载的 USB 根文件系统必须支持通过现有 Minix 文件系统代码路径创建和修改文件。

#### 场景：在根分区写入文件

- **当** USB 启动后进程在根文件系统中创建或覆盖文件时
- **则** 写入成功，且在同一会话中读回内容保持一致

### 需求：初始化顺序

USB 主机控制器、mass storage、GPT 分区注册及块设备设置必须在调用 `super_init` / `mount_root` 之前完成。

#### 场景：初始化序列

- **当** 内核初始化线程执行文件系统设置时
- **则** 在读取根超级块之前，GPT P2 对应的 USB 块设备已存在

### 需求：传统启动路径保持不变

在未启用 USB 启动构建时，系统必须保持现有 IDE 优先的根挂载行为（`DEV_IDE_PART`，失败则回退 `DEV_IDE_CD`）。

#### 场景：ISO 或 master.img 启动

- **当** 内核通过传统 GRUB ISO 或 IDE `master.img` 启动，且未配置 USB 启动时
- **则** 根文件系统仍按现有逻辑从 IDE 分区或光盘挂载
